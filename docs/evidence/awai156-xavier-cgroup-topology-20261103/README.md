# Xavier hybrid cgroup topology: read-only inspection

At approximately 2026-11-03 08:59 UTC, a read-only SSH inspection of Xavier used strict host-key verification against keys advertised in its Tailscale peer record. `/proc/cgroups` reported CPU, CPU accounting, memory and pids enabled, with CPU and CPU accounting in the same v1 hierarchy. Mount inspection showed writable-mount flags for the corresponding v1 mounts and for a cgroup v2 mount named `unified`. The v2 mount's `cgroup.controllers` and `cgroup.subtree_control` were both empty for this observation; its directory was not writable to the SSH user.

The observed systemd user manager's actual `/proc/<MainPID>/cgroup` memberships resolved to existing CPU, memory and pids directories. None was owned by the SSH user; `os.access(..., W_OK)` was false. Reported modes were `0555` for the CPU directory and `0755` for memory and pids. The manager PID start time was unchanged during inspection. Mount-level `rw` and directory-level access describe different checks. `Delegate=yes` as reported earlier is not itself proof that the SSH user can administer the v1 CPU and memory controllers or that systemd user units get the requested limits.

This refines the earlier observation that the root-level `cgroup.controllers` path was absent: Xavier has a hybrid configuration, not proof that all cgroup v2 mounts are absent. It is consistent with, but does not independently prove the cause of, the [oneshot limit mismatch](../awai156-xavier-systemd-limit-probe-20261103/README.md). No cgroup, unit, permissions, daemon or boot configuration was modified. A change to cgroup delegation or hierarchy can affect existing services and requires its own reviewed migration and qualification. This read-only sample does not establish a safe method to change it or qualify a governor.

The observer scripts are diagnostic-only Python, not production tooling. `mounts.py` SHA-256 `9a77a98b5b595327fc6998727d13ebf0b01463fe4208cfea1cae01478b9c7933`; `unified.py` SHA-256 `e1cead5e665d699b8e6aa24d1836299cbac5a3f0d8639a19b0e9a37ac78c1f54`.
