# Cron archive work-directory isolation

The native cron controller now refuses archive work paths overlapping the resident's runtime root, cache, or checkpoint store in either direction. Both the normal cycle and explicit recovery perform the check before creating archive files or invoking the archive. A malformed or missing protected directory is refused. This complements the archive component's store-overlap guard and the controller's dispatch-marker, cursor and acknowledgement collision checks. The comparison is lexical and component-aware; the private host must exclude symlinks, hard links and concurrent path replacement.

On one local ARM64 Mac, a native source-unity fixture composed the current controller path checks, normal cycle and recovery cycle with stubbed storage, archive, clock, lease and workload functions. Separate work paths reached the stubbed archive; work nested in runtime, cache or store was refused, as were a parent containing protected paths and a missing cache path. A similarly prefixed sibling was allowed. Both normal and recovery cases passed; a mutant disabling the new cycle guards exited 1. The checks did not create an archive or exercise a real GitHub repository, inference, lease, filesystem containment or production deployment.
