# Recovery of an uncommitted FIFO transition

When a valid intent records exactly one enqueue or removal, the queue still equals the old state, and `queue.pending` is definitely absent, `recover` now syncs the directory and archives the intent without applying the transition. It returns `fifo/aborted` on exit 0, distinct from `fifo/recovered` for the already-visible new state. This reports journal reconciliation only: callers must separately resolve the original operation and must not infer that a workload was launched, stopped, or safe to retry. Pending files, invalid transitions, and states matching neither journal state still fail closed. The same private-root, trusted-writer, qualified FS2 existence and sync assumptions remain.

On one local ARM64 Mac, an ad-hoc signed native diagnostic passed synthetic old-state enqueue, dequeue, and non-head cancel cases, a committed new-state case, and refusal cases for pending, unrelated state, and invalid transition. It also passed the prior sequential enqueue/dequeue/cancel contract. In a process-kill experiment, a test-only instrumented process was killed after the intent directory sync and before pending creation; the ordinary artifact first refused `front`, returned `fifo/aborted` on recovery, preserved all three original tickets, and subsequently dequeued the original head. The test scripts are observers only; their private temporary paths must be adapted to a newly built diagnostic and scratch directory before rerunning. Earlier crash tests expecting this boundary to remain unresolved describe the previous revision.
