# Synthetic Flint stage and inventory verification

On 2026-11-05 JST, a signed Darwin ARM64 selected-source fixture first ran
the [synthetic full-stage case](../awai149-flint-full-stage-20261105/README.md)
and then called `model-flint-parent-verified-inventory?` against the staged
files and pinned synthetic layout. A Python test operator synthesized ADI2
directory frames and an ADP1 parent frame from path-based `stat` and directory
enumeration. These frames were not produced by the native helpers and are not
authenticated or bound to held file descriptors.

The complete synthetic stage returned `inventory/verified`. Same-size changes
to a metadata file or staged weight, an extra entry, and a malformed parent
frame each returned `inventory/refused`. After restoring the files and
removing the extra entry, the stage verified again. A stage whose metadata
manifest had an incorrect total returned `flint-artifact/staging-unknown`;
the corresponding synthetic inventory verification also refused. The earlier
wrong-pin, overlapping path and corrupted-source-weight controls remained
refused. The private temporary directory and its partial stages were removed
after the diagnostic.

`scripts/verify-flint-stage-inventory-native.py` checks 37 selected function
bodies against the current checkout, builds the archived fixture with pinned
diagnostic tools, signs and verifies the image, and reruns these cases. The
remaining assembled dependencies are historical. Compiler and fixture
processes had a three-second CPU cap, with no hard memory cap. The archived
`operator.py` is the task-specific original with absolute paths and is not an
unattended command.

## Existing native ADI2 helper with held diagnostic FDs

On 2026-11-05 JST, the synthetic stage test was repeated on one local Darwin
ARM64 Mac with the previously signed experimental ADI2 helper instead of
Python-generated ADI2 directory records. The test pinned and verified the
helper's signature and SHA-256, opened the stage root without following a
final symlink, opened `.kapitsa` relative to that root with `O_NOFOLLOW`,
obtained each ADI2 frame from the helper on its corresponding FD, and retained
both FDs while the selected content verifier ran. The operator compared the
FD identities and path observations before/after the verifier.

The complete stage verified; changed metadata, changed staged weight, extra
entry, invalid parent frame, wrong root identity and the partial stage were
refused. The wrong-root control altered the synthetic parent frame consistently
with the wrong expected identity, leaving the actual root ADI2 frame
unchanged. Replacing `.kapitsa` with a symlink was refused by the diagnostic
host's no-follow open; after restoration the stage verified again. These are
bounded controls on a private synthetic tree, not exhaustive race testing.

The helper SHA-256 was
`8f8e63db8e32c532f650bb9504ae4dad29c1e7bff79baf6824339dd1b51746aa`;
`scripts/verify-flint-stage-native-adi2.py` SHA-256 was
`dddeccabcd0f9a356a185ee9092aab21483e6363ba8474f7d32ddeed2dd95a3d`.
The same fixture and diagnostic compiler/packager pins listed above were
used. Compiler, helper and fixture subprocesses had a three-second CPU cap;
no hard memory cap was applied. The task-owned temporary tree was removed.

The ADP1 parent frame was still synthesized by Python from `fstat` and a
no-follow relative `stat`, not generated by the candidate parent helper. The
verifier itself reads stage contents by path, not through the held FDs; the
before/after checks cannot rule out a change-and-revert race or bind those
reads to an immutable snapshot. The Python operator is not a trusted native
host. Real model data, production FS2, authenticated helper composition,
crash recovery, selfhost and governor qualification remain untested.
