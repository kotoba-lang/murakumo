# Supplementary per-process limit for the Linux inference transport

The Linux/systemd `pr-submit` candidate now requests `LimitAS=128M` for the curl oneshot, in addition to its existing `MemoryMax` and `CPUQuota` settings. `LimitAS` is a per-process virtual-address-space limit, not an aggregate resident-memory, GPU, descendant-tree or host reservation. In particular, the observed Xavier cgroup v1 configuration does not enforce the prior cgroup properties in the tested user units; see [the cgroup observation](../awai156-xavier-systemd-limit-probe-20261103/README.md). This change does not qualify or bypass the required governor and host admission.

On Xavier, one short-lived diagnostic systemd user unit with `LimitAS=64M` and `LimitCPU=3s` ran a Python test child. The child read back both hard and soft address-space limits as 67,108,864 bytes and CPU limits as 3 seconds. An 8 MiB mmap succeeded and a 96 MiB mmap failed with ENOMEM. This is a small virtual-allocation test, not an OOM stress test or a whole-process-tree memory limit. A separate 128 MiB test ran the existing curl 7.68.0 against a task-owned synthetic Unix-domain HTTP peer, returned its expected request and response, and cleaned up its test unit and temporary files.

For a closer command-path check, a local native source-unity fixture used the current `pr-local-mtp?` and `pr-submit` to emit the actual systemd-run argument sequence. Config extraction and spawn were stubbed; this is not the full resident or actual wire-20 execution. The observer supplied synthetic request/authorization files and ran that sequence on Xavier against a temporary local Unix peer. systemd reported `LimitAS=134217728`, the test peer received the expected synthetic request and header, curl returned the expected synthetic response, and the unit reached `exited` / `success`. The exact task unit was stopped and checked `not-found` / `inactive`, the peer exited, and the unique task directory was removed. No existing service or real model was touched. These observations do not validate TLS, other systems or curl builds, real MTP, the host's GPU memory or descendant controls, and the full native suite remains unrun. The 128 MiB limit could be insufficient for some curl or TLS configurations; test those actual configurations before deployment.

The diagnostic scripts are test-only Python and require adapting temporary fixture paths.
