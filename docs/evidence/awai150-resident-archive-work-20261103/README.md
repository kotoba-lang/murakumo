# Resident archive work-directory boundary

The resident `archive-native` entry point now rejects a work directory that overlaps the configured runtime root, cache or checkpoint store. It also rejects missing or non-absolute protected roots. The cron coordinator delegates its earlier check to the same function, so normal and recovery flows and direct resident archive calls use the same lexical boundary. The host must still own the paths and prevent filesystem aliases and concurrent replacement.

On one ARM64 Mac, a native diagnostic composed the actual resident path functions with stubbed configuration access. Separate and similarly prefixed paths were accepted; descendants of runtime, cache or store, an enclosing parent, a missing cache and an acknowledgement collision were refused. The same fixture without the new check failed. The earlier native cron normal/recovery fixture was rebuilt with the shared helper and passed, while its guard-bypass mutant failed. Configuration parsing, GitHub, filesystem containment, lease, inference and a production controller were not exercised. New cases were also added to `profile_resident_test.kotoba`; the full native test suite was not run in this observation.
