# Concurrent resident lease and expired-value takeover

A disposable 1-CPU / 1-GiB ARM64 Linux VM ran three native lease-group
voters on distinct loopback addresses and test wrappers around the current
`rt-current-lease` path for two independently configured nodes. A synthetic
operator-signed topology enabled both nodes; an RFC 8032 public test key and
synthetic HMAC token were used. Each group had its own task-owned directory.

In one concurrent race, both resident processes requested epoch 1. `b70`
received a lease, `k16` received no lease, and a subsequent `k16` request
also returned no lease. In a separate fresh set of groups, a native proposer
chose an already-expired `b70` epoch-1 value. The `k16` resident obtained an
epoch-2 lease; a subsequent `b70` request returned no lease. The epoch-2
state file existed in all three group directories. Each process and directory
belonged to this fixture; the VM was stopped and deleted afterward.

This is one race and one sequential expired-value takeover, with one shared
VM, filesystem and clock. It does not prove safety across physical hosts,
clock faults, state rollback, real workloads, or power loss. It does not stop
an old workload or fence its effects at a sink. No bot turn or inference ran.
The scripts are test-only and use fixed paths; adapt them before reuse.

`topology.py` is the existing public-key test topology generator modified to
enable both synthetic nodes. `seed-generator.py` derives the test-only expired
proposer from the previously built resident unity source. The latter and group
sources are generated by [the prior quorum fixture](../awai150-resident-quorum-20261103/).
